# main.css

Global styles: CSS custom properties for the color palette (dark theme by default), page layout, the patch-editor grid, the timeline/transport view (including the loop-region overlay), the piano-roll note editor, the mixer channel strips, and the header's project controls. `.timeline-block`/`.piano-roll-note`/`.timeline-ruler` use `touch-action: none` so drag/resize works as a touch target, not just a mouse target. `.timeline-track-header`'s width (120px) is duplicated as `TRACK_HEADER_WIDTH` in [timeline.js](../js/ui/timeline.md) — keep them in sync; `.piano-roll-key`'s 20px height is likewise duplicated as `ROW_HEIGHT` in [pianoRoll.js](../js/ui/pianoRoll.md) (the grid's row gradients are generated in JS from that constant).

**Phase 10 touch pass:** every small icon/toggle button (`.timeline-track-remove`, `.timeline-block-remove`, `.mixer-toggle`, `.mixer-effect-header button`, `.project-controls button`, `.transport-bar button`, etc.) has an explicit `min-width`/`min-height` (24–40px) rather than shrinking to fit its glyph — measured on a real mobile viewport before and after (`timeline-track-remove` went from 12×14px to 28×28px, for example) rather than guessed. Resize-handle widths (`.timeline-block-resize`, `.piano-roll-note-resize`) were widened for the same reason. Since Phase 16 the piano roll has its own zoom (20–240 px/beat), so cramped notes can be enlarged.

As more views are added, prefer one stylesheet per major UI area over growing this file indefinitely; the timeline + piano-roll rules are already large enough that splitting them into their own files would be reasonable the next time this file is touched.

Phase 14–15 additions: the patch editor's sectioned grid (`.patch-section`, `.patch-readout`), selection highlights (`.timeline-track-header--selected`, `.timeline-block--selected`, `.mixer-strip--selected`), the `.timeline-view-bar`/`.block-toolbar` rows, mini note previews (`.timeline-block-note`), and lane gridlines driven by the per-lane `--bar-px`/`--beat-px` custom properties. Track headers are sticky (z-index above blocks and the playhead).

Phase 16: piano-roll toolbar, sticky key column with an active state, the "outside the block" overlay, and the velocity lane (`.piano-roll-velocity-*`). The key column and velocity label share a 56px width so the lane lines up with the grid.

`.patch-field` is a two-row grid, and `.patch-range` uses `display: contents` so its slider can span the second row at full width. Phase 17: `.patch-learn` (MIDI-learn button states) and the active Record button. `#keyboard-status` is hidden on touch-only devices (`hover: none` + `pointer: coarse`). The mixer's add-effect controls got the 32px minimum touch size that Phase 10 missed.
