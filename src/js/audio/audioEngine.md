# audioEngine.js

Owns the single `AudioContext` and master gain node (lazily created on the first `note:on`, so we don't trip the browser's autoplay-gesture policy). Subscribes to `note:on`/`note:off` on the shared [eventBus](../core/eventBus.md) and forwards them (as live, immediate notes) to a [synthEngine](./synthEngine.md) instance, which owns polyphony/voice management. Also holds the current [patch](./patch.md) and exposes `getPatch()`/`setPatch()` for UI consumers like [patchEditor.js](../ui/patchEditor.md). `ensureAudioContext()`/`getMasterGain()` are the public entry points other modules (e.g. [transportController.js](../core/transportController.md)) use to get at the same context/output instead of creating their own. `scheduleNote()` is the separate pre-scheduled-playback path the sequencer uses (see [synthEngine.js](./synthEngine.md)'s "Deviation" note) — it does not go through `note:on`/`note:off` at all.

Since Phase 6, `ensureContext()` also creates a [mixer](./mixer.md) (`createMixer(audioContext, masterGain)`), which takes over `masterGain`'s downstream connection (`masterGain -> masterChain -> destination` instead of straight to `destination`) — `getMixer()` is the accessor other modules use to reach it. `masterGain` itself is otherwise unchanged: live notes and the mixer's per-track buses all still sum into it. Also subscribes to `track:removed` (emitted by [timeline.js](../ui/timeline.md) when a track is deleted) to dispose that track's now-orphaned mixer bus — without this, a removed track's gain/pan/effect nodes would stay connected and leak. `resetMixer()` (used by [projectControls.js](../ui/projectControls.md) on New/Import) tears down and rebuilds the whole mixer at once, for the same reason at a larger scale.

`initAudioEngine()` must be called once at startup before any `note:on` events are emitted. `ensureContext()` also resumes a suspended context on every note-on, which covers Chrome's per-tab autoplay suspension after inactivity. The synth engine itself isn't created until `ensureContext()` runs (it needs the context/master gain to exist first), so `setPatch()` calls before the first note-on only update `currentPatch` — that's fine, since the engine reads it via `synthEngine.setPatch(currentPatch)` once it's constructed.
