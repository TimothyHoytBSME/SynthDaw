# effectTypes.js

The effect registry: `EFFECT_TYPES` maps a type key (`"delay"`, `"distortion"`, `"reverb"`, `"compressor"`, `"chorus"`, `"eq"`) to `{ label, create, paramDefs }`, where `create` is that effect's factory from [effects/](effects/) and `paramDefs` is a config-driven list (`{ name, label, min, max, step, default }`) that [mixer.js](../ui/mixer.md) uses to generate sliders generically — the exact same pattern [patchEditor.js](../ui/patchEditor.md) uses for synth parameters. Adding a new effect type means: write the factory in `effects/`, add one entry here, and the mixer UI picks it up automatically — no UI code to touch. A paramDef may be `kind: "select"` with `options` (a dropdown, string value), and `syncedBy: "<param>"` marks a slider the UI disables while that param isn't `"off"`. An entry may define `resolveParams(params, tempo)` to derive what the node really receives: the delay uses it for **tempo sync** (`sync` ∈ [tempoSync.js](./tempoSync.md)'s divisions; when synced, `time` = the division's length at the project tempo, capped at the 2 s delay buffer). `resolveEffectParams(type, params, tempo)` applies it (or returns `params` unchanged). `defaultParamsFor(type)` builds a fresh `{ name: default, ... }` object from `paramDefs`, used whenever a new effect instance is added.
