# exportRender.js

Offline render of the whole project to an `AudioBuffer` (then [wavEncoder.js](./wavEncoder.md) -> file). It builds a throwaway [synthEngine](./synthEngine.md) plus a [mixer](./mixer.md) on an `OfflineAudioContext` at `ENGINE_SAMPLE_RATE` (48 kHz, from [audioEngine.js](./audioEngine.md), so the file matches live playback), calls `mixer.syncProject(project)`, and schedules the notes from [`playableNotes`](../core/project.md), clipped to block bounds just like live playback. This needs no DSP duplication because every audio module takes its `AudioContext` as a parameter. Keep them context-agnostic: a module that reaches for the live context would silently render into the wrong graph.

**Chunked scheduling (2026-10-15):** notes are sorted by start and added `CHUNK_BEATS` (4) at a time from `OfflineAudioContext.suspend()` callbacks, 50 ms before each chunk starts, instead of all up front. A voice scheduled for the future still runs its nodes (outputting silence) from time zero, so up-front scheduling made render time grow with the note count: Neon Riptide (2619 notes) took 12.5 minutes headless. Chunked, Neon Pulse renders 2.8x faster and the output is identical to within 1.5e-5 (seeded-random A/B). `renderProjectToBuffer(project, { onProgress })` reports progress (0..1) per chunk; [projectControls.js](../ui/projectControls.md) shows it on the Export WAV button.

Length = the last playable note's end + `RELEASE_TAIL_SECONDS` (2s), with a minimum of 1s.
