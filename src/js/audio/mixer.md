# mixer.js

Owns the per-track audio buses and the master [effect chain](./effectChain.md), and keeps them in sync with the plain-data mixer state on [Track](../core/project.md)/`project.master`. Signal flow per track: `trackBus.gainNode` (volume) → track's `effectChain` → `StereoPannerNode` → the shared `masterGain` (created by [audioEngine.js](./audioEngine.md)) → `masterChain` → `audioContext.destination`. Live-played notes (on-screen piano/MIDI — see [pianoTrigger.js](../ui/pianoTrigger.md)) skip track buses entirely and connect straight to `masterGain`, so they still pass through master effects but not any track's effects or volume/pan — see the "Deviation" note in [project.md](../core/project.md) for why (no live "selected track" concept exists yet).

**Rebuild, don't diff:** `syncTrackEffects`/`syncMasterEffects` don't try to patch an existing chain to match a changed effect list — they remove every stage and re-add from scratch each time (`rebuildEffects`). Given effect chains are short, this is simpler and just as correct as diffing, matching the project's general "re-render from source of truth" pattern.

`syncTrackGains(project)` recomputes every track's *effective* gain in one pass — necessary because solo isn't a per-track property in isolation: soloing any track silences every non-soloed track, so a change to one track's mute/solo/volume/pan requires recomputing all of them together. `getTrackBus(trackId)` lazily creates a bus on first use (matching the project's general lazy-audio-graph-creation pattern) with sensible defaults (gain 1, pan 0, no effects) that already match a freshly-added [Track](../core/project.md)'s defaults, so a brand new track needs no explicit sync call.

`reset()` (added for Phase 9's New Project / Import — see [projectControls.js](../ui/projectControls.md)) tears down every track bus and rebuilds the master chain from scratch, rather than trying to reconcile old buses against a wholesale-replaced project's tracks (whose ids carry no relationship to the old ones). `masterChain` is a `let`, not `const`, specifically so `reset()` can swap in a fresh one that every other method's closure picks up automatically.
