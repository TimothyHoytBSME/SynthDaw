# synthEngine.js

Polyphony manager sitting between [audioEngine.js](./audioEngine.md) and [voice.js](./voice.md): tracks one active voice per note number, enforces `MAX_VOICES` (8) via oldest-voice stealing (insertion-order, not fixed — a stolen/retriggered voice always gets a fast forced release via `voice.stop(true)`, never a hard cut), and holds the current [patch](./patch.md) that new voices are built from. `setPatch()` only affects voices created *after* the call — already-sounding notes keep the patch they started with, which is standard synth-engine behavior and avoids retroactively distorting live envelopes.

Re-pressing an already-sounding note (`noteOn` called again before its `noteOff`) retriggers: the old voice is force-stopped and a new one starts, rather than being ignored or stacked.

**`scheduleNote(note, velocity, startTime, durationSeconds, destinationOverride)`** is a second, separate path used by the sequencer ([transportController.js](../core/transportController.md)) for pre-scheduled playback: it creates a voice and schedules its `start`/`stop` at exact future `AudioContext` times up front, entirely bypassing `activeVoices`/polyphony-stealing. `destinationOverride` lets the caller route a specific note into its track's mixer bus ([mixer.js](./mixer.md)) instead of the synth engine's default `destination` — this is how per-track volume/pan/effects apply to sequenced playback while the live-play path (`noteOn`/`noteOff`) keeps using the fixed default. **Deviation/known limitation:** live-played notes (MIDI/on-screen) and sequenced playback don't share one voice-count budget — a busy sequence plus heavy live playing could together exceed `MAX_VOICES` worth of simultaneous oscillators with no shared stealing between the two pools. Acceptable for now (sequenced parts are typically not being played live over at the same time); revisit if it becomes audible glitching under real use.
