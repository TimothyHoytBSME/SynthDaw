# voice.js

Builds one polyphonic voice's full Web Audio graph from a [patch](./patch.md): N oscillators (each through its own mix `GainNode`) → one shared `BiquadFilter` → one amp `GainNode` (the ADSR target) → `destination`. An optional LFO (`OscillatorNode` + depth `GainNode`) connects either to every oscillator's `detune` param (`target: "pitch"`, vibrato) or to the filter's `frequency` param (`target: "filter"`, wobble) — skipped entirely when `patch.lfo.depth` is 0, so a silent LFO costs nothing.

`scheduleEnvelope` drives both the amp gain and the filter-cutoff envelope with the same attack/decay/sustain shape (different base/peak values). `scheduleRelease` uses `AudioParam.cancelAndHoldAtTime(atTime)` — deliberately *not* `cancelScheduledValues` + `setValueAtTime(param.value, ...)` — because the latter reads `param.value` synchronously in JS at call time, which is wrong whenever `atTime` is in the future (as it is for [synthEngine.js](./synthEngine.md)'s `scheduleNote`, which schedules a note's start *and* stop together, up front). `cancelAndHoldAtTime` is evaluated by the audio thread at `atTime` itself, so it holds whatever value the envelope will actually have reached by then, correctly for both a live "release now" call and a future pre-scheduled one.

`start(atTime)`/`stop(immediate, atTime)` both default to `audioContext.currentTime` when `atTime` is omitted (the live-play path), but accept an explicit future time for sequenced playback. `start()`/`stop()` together are single-use — a voice cannot be restarted after `stop()`, matching `OscillatorNode.stop()` being terminal.

`stop(immediate)`: `immediate = true` (used when [synthEngine.js](./synthEngine.md) retriggers or steals a *live* voice) forces a fast fixed release instead of the patch's own release, so cutting a voice short never clicks. Sequenced notes always use `immediate = false` (their own patch release, scheduled precisely).
