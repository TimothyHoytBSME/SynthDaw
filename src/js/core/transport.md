# transport.js

Audio-accurate play/pause/stop clock, independent of any UI. Position tracking (`getPositionBeats()`) is computed on demand from `audioContext.currentTime`, not incremented by a timer — so it never drifts and stays correct even if the tab is throttled. `onClick` fires once per beat using the classic Web Audio "lookahead scheduler" pattern (`setTimeout` polls every 25ms, but each event's actual audio time is computed precisely and handed to the caller, which schedules the real sound at that exact `AudioContext` time — see [click.js](../audio/click.md)); this is what the plan's "audio-accurate scheduling, not `setInterval` drift" note refers to.

`setTempo()` preserves the current beat position across a tempo change (re-anchors `startBeat`/`startContextTime` first) so changing tempo mid-playback doesn't jump the playhead. `pause()` freezes position; `stop()` resets to beat 0. This module only emits `transport:play`/`pause`/`stop`/`tempo` on the [eventBus](./eventBus.md) for anything that wants to react (nothing does yet) — the UI polls `getPositionBeats()` directly via `requestAnimationFrame` for the playhead instead of subscribing, since that needs to run every frame, not just on state-change events.
