# transportController.js

Glue between the UI-agnostic [transport.js](./transport.md) clock and the audio side. Lazily creates a single `transport` instance on first `getTransport()` call (needs an `AudioContext`, obtained via [audioEngine.js](../audio/audioEngine.md)'s `ensureAudioContext()`), and drives `transport`'s one `onSchedule` hook with two independent consumers of the same lookahead window:

- **Metronome** — schedules a [click](../audio/click.md) on every integer beat in the window when `metronomeEnabled` is true, accenting beat 1 of each bar via `beatsPerBar`.
- **Note sequencer** — walks every track/block/note in the current `project` ([project.js](./project.md)) and, for any note whose *absolute* beat position (`block.startBeat + note.startBeat`) falls in the window, calls `scheduleNote()` on [audioEngine.js](../audio/audioEngine.md) with the exact `AudioContext` start time, duration, and — since Phase 6 — that note's track's mixer bus (`getMixer().getTrackBus(track.id).gainNode`) as the destination, so per-track volume/pan/effects apply to sequenced playback. This is genuinely pre-scheduled (start and stop both handed to the audio graph up front, not polled again later), not a live event — see the "Deviation" note in [synthEngine.js](../audio/synthEngine.md).

`getTransport({ beatsPerBar })` is how [timeline.js](../ui/timeline.md) both supplies the current time signature and retrieves the shared transport — pass `beatsPerBar` on the call that changes it (e.g. from a time-signature input), omit it otherwise. `setProject(project)` must be called once (from `main.js`) before playback will produce any notes — without it, only the metronome sounds.
