# mixer.js

Renders one channel strip per track plus a master strip: volume/pan sliders and mute/solo buttons (tracks only — mute/solo isn't meaningful for master), each wired to a [project.js](../core/project.md) setter followed immediately by [`getMixer().syncTrackGains(project)`](../audio/mixer.md) (or `syncMasterVolume` for master) so the change is audible right away. Each strip also gets an effects section (`renderEffectsSection`, shared between track and master strips) built generically from [effectTypes.js](../audio/effectTypes.md)'s `paramDefs` — the same config-driven slider pattern as [patchEditor.js](./patchEditor.md), just per-effect instead of per-patch.

Re-renders entirely (`render()`) on every effect add/remove and whenever `project:tracks-changed` fires on the [eventBus](../core/eventBus.md) (emitted by [timeline.js](./timeline.md) after adding/removing a track) — it does not own track add/remove UI itself, only listens for it, since track structure is timeline's responsibility. Per-effect param sliders update in place via `setParam`/`syncTrackEffects` without a full strip re-render, so dragging a slider doesn't reset scroll position or steal focus.
