# pianoRoll.js

Note editor for one [block](../core/project.md): `renderPianoRoll(container, block, { beatsPerBar })`. [timeline.js](./timeline.md) opens it in a panel below the arrangement.

**Layout:** a toolbar (zoom 20–240 px/beat, snap 1 … 1/16 beat, a **Quantize notes** button that snaps the selected notes' starts, or every note's with nothing selected, to the snap grid, and a how-to hint), then a scroll area with a sticky key column (the full MIDI range, 0–127, as 20px rows) beside the grid, then a velocity lane whose horizontal scroll is kept in sync with the grid. Grid lines and black-key row shading are CSS gradients built in JS: bar, beat and row lines plus a 12-row stripe period aligned to `HIGHEST_NOTE`. There are no per-row elements. A playhead line sits in the grid: `setPianoRollPosition(beat)` (called from the timeline's animation loop while a roll is open) places it at the position relative to the block, hidden while the playhead is outside the block.

**Interactions:**
- Click empty grid: add a note at the snapped beat, using the last placed/resized length (clamped to the block end) and velocity 100. It's previewed audibly and becomes the selection.
- **Selection (2026-10-15):** click a note to select it; Shift/Ctrl-click toggles notes in and out; drag on empty grid draws a marquee that selects every note it touches (Shift adds to the selection); Ctrl+A selects all; Esc clears. Selected notes get a white outline. The selection is module-level (`selection`), so it survives re-renders of the same block and is cleared when another block opens; ids of deleted notes are pruned on render.
- Drag a note: moves it (and every other selected note) in time *and* pitch, and each new pitch of the grabbed note is previewed. The whole group's delta is clamped by its extremes (`moveGroup`), so relative positions never change and nothing leaves the block or the MIDI range. A plain click on one of several selected notes narrows the selection to it.
- Drag the right edge: resizes every selected note by the same delta (each clamped to the block end), which also becomes the default length for new notes.
- Keys while the roll is open, forwarded by [keyboardShortcuts.js](../core/keyboardShortcuts.md) as a `pianoroll:key` request: Delete/Backspace removes the selection; ↑/↓ transposes it by a semitone (Shift: an octave), all-or-nothing like block transposition; Ctrl+C/X copy/cut to an in-memory note clipboard (relative to the earliest start); Ctrl+V pastes at the snapped playhead when it's inside the block, else at the block start; Ctrl+D duplicates the selection right after its end. Pasted notes that would start past the block end are dropped with a status message. Keys with nothing selected are left to the block shortcuts (except Delete and the arrows, which never fall through to the block while a roll is open).
- Double-click or right-click a note: delete that one note. There's no inline "×" button, since notes are often too small for one.
- Velocity lane: drag a note's bar vertically; if the note is selected, every selected note takes the same velocity (so a chord's stacked bars are no longer a problem: marquee the chord, then drag any bar). Note opacity reflects velocity.
- Press a key in the key column to hear that pitch (held until release). This replaces the removed on-screen piano's "audition a note" role. Previews go through the normal `note:on`/`note:off` path, so they play the selected track's instrument.

**Rendering:** add/delete does a full re-render into the same container, preserving scroll. A *fresh* container (opening a block, or the timeline refreshing after a transpose) centres the view on the block's notes (or C4 if empty), so transposed notes never end up off-screen. Drags update elements in place via a `cells` map (note id → cell, label, velocity bar); `refreshNoteElements` restyles one note after any group edit. Edits emit `block:notes-changed { blockId }` so the timeline redraws that block's miniature. Notes past the block's end (after the block was shrunk) are drawn under a dashed, shaded "outside" region: kept, but not played (see `playableNotes`).

`settings` (zoom, snap, last length), `selection` and the note clipboard are module-level, so it persists across re-renders and between blocks. `ROW_HEIGHT` (20) must match `.piano-roll-key`'s height in `main.css`.
