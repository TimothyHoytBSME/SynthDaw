# projectControls.js

Seven controls in the header: **Undo**/**Redo** ([history.js](../core/history.md), disabled via a `disabled` attribute kept in sync with `history:changed` events rather than always-enabled), **New Project** (confirms, then replaces the current project's contents with an empty one plus a default track), **Export JSON** (downloads `synthdaw-project.json` via a blob URL — the manual, portable backup/sharing path), **Export WAV** (renders the whole project offline via [exportRender.js](../audio/exportRender.md) and downloads the result as a real audio file via [wavEncoder.js](../audio/wavEncoder.md) — disables itself and shows "Rendering…" for the render's duration, since it's not instant), **Import JSON** (hidden file input triggered by a visible button, parses and replaces), and a status readout reflecting `project:changed`/`project:saved` from the [eventBus](../core/eventBus.md) (via [persistence.js](../core/persistence.md)'s autosave).

New/Import both call `replaceProjectContents()` ([project.js](../core/project.md)) rather than swapping to a new object — every other module ([timeline.js](./timeline.md), [mixer.js](./mixer.md), `transportController.js`) holds a reference to the *original* project object, so mutating it in place is what lets `onReplaced()` (passed in by `main.js`, which just re-renders the timeline/mixer into cleared containers) work without re-wiring every module's project reference. Both also call `resetMixer()` ([audioEngine.js](../audio/audioEngine.md)) first — the old tracks' mixer buses are keyed by ids that may not exist in the new data, so the whole audio-side mixer state is torn down and rebuilt fresh rather than reconciled.
