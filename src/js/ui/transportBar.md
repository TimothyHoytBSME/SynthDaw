# transportBar.js

`createTransportBar(project, { onLayoutChange, onTransportAction })` returns `{ element, setPosition(beat), dispose }`. The bar has Play/Pause/Stop, a position readout (`bar.beat`), the master [level meter](./levelMeter.md), tempo, beats-per-bar, metronome and loop (enable + start/end in beats). After Stop come **● Rec** (toggles [recorder.js](../core/recorder.md) on the selected track, and turns red while recording) and a **Quantize** checkbox for takes. An audio-status note ("🔇 Audio is paused by the browser. Click anywhere to enable it.") is shown whenever the AudioContext exists but isn't running (`audio:state`), and hidden otherwise, so a browser block is never just silence. If Play has to wait more than 1s for audio (the browser still refuses to start it), a `status:message` asks the user to click the page. `dispose()` unsubscribes its listeners and stops the meter. `checkboxField` is exported for the timeline's view bar.

Tempo, beats-per-bar and loop go through [project.js](../core/project.md) mutators, so they're undoable and saved, and [transportController.js](../core/transportController.md) pushes them into the transport. Number fields apply on `change` (commit), not on every keystroke, and are re-displayed with the clamped value. `onLayoutChange` tells [timeline.js](./timeline.md) to redraw (ruler, loop overlay). `onTransportAction` lets it sync the playhead immediately.

`formatPosition(beat, beatsPerBar)` is exported for other views (the block toolbar uses it).
